# 应用目录与授权

应用分为默认、系统、内部、外部四类。默认入口由数据库 `kind=default` 决定，既有目录包括个人中心和文件；应用管理与统一身份认证属于系统应用，需要显式授权。系统/内部应用默认拒绝，按统一身份认证中的直接用户授权和所属角色授权并集开放。目录、搜索和 Dock 不显示无权访问的应用，业务 API 每次重新验证授权，不能通过手工输入地址绕过。

Token One 门户、控制台、文档分别使用 `token-one`、`token-one-console`、`token-one-docs`。控制台访问由其独立应用授权决定，不再根据门户账户的 admin 角色推断。统一身份认证仅管理功能，管理接口同时校验应用授权及身份管理员资格。

应用管理列出当前可访问的内置应用与用户自己的外链。系统/内部应用在前后端均只读。个人外链按用户隔离存储，使用 CSRF 校验和原子更新；不读取或复制第三方 Cookie，也不将统一认证令牌注入外链。

外链直接由浏览器 iframe 加载，保留完整查询参数与锚点，不走业务 API 代理、不接收可信桌面 SDK 消息。平台会话主机及其子域禁止作为个人外链重复添加。第三方站点是否允许嵌入、能否复用其登录状态取决于站点策略和浏览器存储分区；桌面保留在浏览器中打开入口。

## 名称与恢复

平台应用的运行目录位于服务数据库的 `desktop_applications` 表，包含入口、上游、允许路径、窗口尺寸、授权 audience、启停和排序；变更不再要求修改 Java 源码或重新打包 `jar`。`desktop_application_audit` 保存管理变更前后配置与执行人。统一身份授权仍由身份中心负责，不复制到桌面数据库；服务发布与契约仍由 `service_*` 表负责。

首次迁移由数据库管理账号执行 `java -jar app.jar desktop-applications migrate <注册清单.json>`。命令只导入显式清单；同 ID 同配置可重复执行，同 ID 不同配置拒绝覆盖。已有数据仅升级表结构时执行 `desktop-applications schema`。运行账号只需要目录表读取权限，不能隐式执行 DDL。完整格式与命令见 [应用注册唯一来源](../../mg-platform-kernel/docs/application-registration.md)。

运行时名称、图标键、入口和访问规则只来自数据库。公共 JSON 为内核提供桌面名称，并继续作为前端图标资源配置。数据库不可用、表未迁移、账号失权或空表时拒绝启动，不回退内置目录；运行中失去读取权限返回 503。注册、停用、排序和配置更新在后续请求读取时生效，停用项仍保留服务历史与外链主机保护。

刷新时保存应用与页面，不保存注册弹窗草稿。多个普通应用依据当前视口重新错位排列，保持原层级和最小化状态；不沿用可能来自旧分辨率的边界位置。单个窗口仍可保留其铺排模式。

桌面背景不再摆放应用快捷图标。应用从“所有应用”进入；网格顺序和 Dock 固定顺序分开保存到用户偏好。拖动统一采用 Pointer Events，支持网格排序、拖到 Dock 指定位置固定、Dock 排序及拖出取消，Escape 放弃拖动。未联网时先保存本地偏好，恢复网络后同步。
