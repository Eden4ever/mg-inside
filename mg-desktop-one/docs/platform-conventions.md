# 平台应用范式

目标：让业务应用主要实现内容页面，通过简单 JSON 配置复用平台框架。公共文件维护一份，构建时进入各应用产物，独立浏览器访问不依赖桌面静态资源。

## 公共外壳、布局、内容

所有应用共享登录会话、网页页头、用户入口、主题语义和桌面通信。业务权限最终由业务后端判定，配置里的权限标识只用于界面呈现。

| 布局 | 适用场景 | 平台提供 | 应用提供 |
| --- | --- | --- | --- |
| 标准应用 | 管理后台、个人中心、指标业务 | 页头、应用导航、底部收起、内容容器 | 页面组件、路由/菜单配置、业务操作 |
| 文档阅读 | 接口文档、使用说明、帮助中心 | 页头、统一认证、桌面接入 | 文档目录、正文、本页目录、阅读交互 |

标准应用导航只提供单层、两级、分组三种模式。阅读布局的目录不是第四种应用导航，它属于文档内容结构，不强制渲染通用业务图标菜单。

## 配置边界

- JSON 配置应用标识、名称、默认页面、布局、品牌、顶部显示项、页面标题、菜单图标与分组。
- 页面组件和图标通过字符串名称映射到明确注册表；配置不执行函数，不拼接任意模块路径，不注入 HTML/CSS。
- Schema 标明版本并验证必填项、枚举、引用和拼写；运行时给出中文错误，避免配置错误变成空白页。
- 原站点密钥、访问令牌、服务凭据与真实授权校验不进入前端配置。
- 复杂表单流程、指标编辑、用量计算、上传解析等保留业务代码。配置表达结构，不发展成另一套编程语言。
- 先以个人中心为配置化样板，随后将既有应用逐步迁入；不能把“引用了公共样式”说成“整个应用已配置化”。

## 已确认的交互基线

- 标准应用侧栏默认收起，展开/收起位于底部，不占页头。
- 侧栏底部不放个人中心、员工门户等跨应用快捷入口。
- 桌面嵌入隐藏网页页头；桌面窗口标题区透明，颜色来自应用。
- 网页版复用 ApplicationHeader，个人中心入口从账号区访问。
- 顶部窗口控制提供独立浏览器打开当前页面的按钮。
- 最大化、半屏与浮窗遵循统一零边距计算；普通浮窗可进入 Dock 区域，铺排窗口贴到 Dock 顶部。

JSON Schema、组件接口和引入方式以 `mg-platform` 的 README 及包内文件为准。正式内部包发布后按版本升级，避免一个平台变更未经验证同时改变所有线上业务。

## 2026-09-08 后续交互修订

- 桌面窗口使用毛玻璃贯通标题栏与标准导航，独立浏览器保留应用原背景。
- 窗口按钮采用Windows习惯，左侧为半屏摆放，右侧为外部打开、最小化、最大化/还原、关闭。摆放后仍可拖动和缩放。
- 个人中心统一提供个人资料、账号安全、桌面设置、通知和退出登录。
- 阅读型应用采用经典文档站排版，宽屏文字目录默认展开，例外于标准应用默认折叠规则。
- 业务必须完整上报dirty/busy；SDK补充可见弹窗保护。关闭/移动等本地操作不能以网络请求作为先决条件。
