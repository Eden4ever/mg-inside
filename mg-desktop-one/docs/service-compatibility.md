# 服务契约兼容检查

2026-09-09，服务端与服务管理前端已发布 `20260909T023424Z`。本批把参数和响应的结构比较接入前后端共用的 `compareContractVersions`。服务版本号本身不是兼容依据，实际提供方是否按契约实现也需要独立验证。

请求按旧版允许值集合包含于新版允许值集合检查；响应按新版允许值集合包含于旧版允许值集合检查。例如，请求 `owner.maxLength` 从 100 放宽到 200 可证明结构兼容，反向切换需要审阅；响应新增必填保证属于收窄，取消旧必填保证需要审阅。比较结果返回操作、结构位置、说明及 `compatible`、`review` 或 `baseline` 结论。

基本规则涵盖类型、枚举与常量的交集、数值上下界、整数倍数关系、字符串长度、相同正则、数组元素与数量/唯一性、对象字段/必填/额外字段及字段数量。仅在充分证明包含关系时返回结构兼容；无法证明不表示已经证明业务不兼容。

OpenAPI 层同时比较参数必填和序列化、正文必填、媒体类型、multipart 编码、响应状态、响应头及认证方案。操作参数覆盖同名同位置的路径参数，响应头名称不区分大小写，响应码按精确状态、范围状态、default 的优先级匹配。删除原有响应正文、删除已有参数/响应头、schema/content 切换和有效认证变化需要审阅。无关的未使用认证方案、说明与等效显式默认序列化不产生差异。

接口详情显示结构位置及结论；首次添加契约显示“无结构基准”。启用时，后端重新计算差异，只有没有待审阅结构变化才无需 `allowContractChange`。需要审阅的变化仍须管理员明确确认；前端结论不能绕过后台。并发修订、受控部署及操作清单破坏性变化检查继续独立执行。
