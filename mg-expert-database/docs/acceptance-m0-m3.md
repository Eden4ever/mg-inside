# M0-M3 验收标准

本文件定义“营商环境指标知识库”从领域契约到研究工作台的可验收边界。M4 的真实 AI 模型调用、SSE 流式对话、导出任务和生产部署不在本次 M0-M3 验收内；但建议、依据、修订、发布的数据契约必须在 M0 固化。

## M0 领域契约与导入准备

### 交付物

- [domain-model.md](domain-model.md)：统一术语、角色、状态机、AI边界与核心实体。
- [research-module-schema.json](research-module-schema.json)：八模块固定编码、字段类型、必填阶段和研究记录约束。
- 与工作簿字段的导入映射清单：先维护在导入实现的代码/测试中，不能由前端页面临时拼接。

### 必须通过

| 编号 | 验收项 | 证明方式 |
| --- | --- | --- |
| M0-01 | 研究记录只能绑定三级指标 | 对一级、二级节点创建记录返回业务校验错误；三级节点可成功创建 |
| M0-02 | 每条记录固定拥有八个模块 | 新建记录后断言模块数为 8，且键集合正好为 `portrait`、`policy`、`data`、`quality`、`governance`、`rectify`、`optimize`、`contacts` |
| M0-03 | 字段契约有效 | `research-module-schema.json` 通过 JSON 语法和 JSON Schema 自校验；八模块编码、排序、字段 ID 均唯一 |
| M0-04 | AI 不被建模为专家人员 | 数据模型中无“专家人员库”作为研究必填模块；AI 输出只能创建 `AISuggestion`，无直接更新研究正文或发布接口 |
| M0-05 | 依据、建议、修订、发布规则可追溯 | 契约覆盖 `Evidence`、`AISuggestion`、`ResearchRevision`、`IndicatorVersion`，且定义不可变修订和发布后只读 |
| M0-06 | Excel 映射不丢失核心语义 | 至少覆盖指标画像、政策、公式/口径/数据链路、质量、整改、优化、条块关系、责任单位八类字段；空白单元不当作已确认事实导入 |

### 需业务确认的输入

- 正式指标目录、三级指标编码、版本号和适用地区。
- 权重、前沿值、标杆案例的权威数据源和复核责任。
- 联系方式的个人信息处理等级及可见范围。

## M2 指标体系与三级指标目录

### 用户验收路径

1. 创建一个指标体系，填写名称、年度、区域和版本号。
2. 在该版本下导入或维护一级、二级、三级指标树。
3. 通过树搜索定位三级指标；匹配时保留完整一级/二级父级路径。
4. 选择三级指标进入研究工作台；选择一级或二级时只展示汇总信息，不提供新建研究记录按钮。
5. 发布一个版本后尝试修改目录，系统拒绝并提示复制新版本。

### 必须通过

| 编号 | 验收项 | 证明方式 |
| --- | --- | --- |
| M2-01 | 三级指标树完整 | 支持 1/2/3 级节点增删改查、排序、展开收起和按名称/编码搜索 |
| M2-02 | 树完整性校验 | 拒绝循环父子关系、非法层级、同父节点重复编码、三级节点添加子节点 |
| M2-03 | 研究记录唯一性 | 对同一 `(指标体系版本, 三级指标)` 重复创建记录返回冲突或返回同一记录 |
| M2-04 | Excel 导入可预检 | 显示行号、字段、错误原因；正式写入仅在预检通过后执行；导入过程和结果可审计 |
| M2-05 | 版本隔离 | 复制版本后指标树和研究记录为可编辑副本，源已发布版本保持不变 |
| M2-06 | 目录操作授权 | 仅 `catalog_manager` 与 `system_admin` 可维护目录；`researcher` 只能研究被授权三级指标 |

## M3 三级指标研究工作台

### 用户验收路径

1. 打开三级指标后，默认显示“查看”状态和八个模块，不出现可编辑表单控件。
2. 选择一个模块进入编辑；其他模块仍为查看状态。
3. 修改字段后取消，重新进入查看应保持保存前内容；保存后应生成新的修订并回到查看状态。
4. 切换三级指标或模块时，如果当前有未保存修改，系统要求保存、放弃或继续编辑。
5. 为字段关联政策、案例或数据依据；对待核验依据进行标记。
6. 提交模块确认；缺少确认必填字段或有效依据时，系统定位具体字段并阻止提交。
7. 审核人确认或退回模块；退回原因在研究者工作台可见，原修订可追溯。

### 必须通过

| 编号 | 验收项 | 证明方式 |
| --- | --- | --- |
| M3-01 | 八模块展示与顺序固定 | 页面和接口按 Schema 的 `displayOrder` 展示，模块不可被用户删除或改名 |
| M3-02 | 默认查看、逐模块编辑 | 首次加载无可输入表单；点击某模块“编辑”后仅该模块进入编辑会话 |
| M3-03 | 保存、取消、冲突保护 | 取消不落库；保存创建不可变 `ResearchRevision`；陈旧 `revisionNo` 保存返回冲突且不覆盖新内容 |
| M3-04 | 字段校验 | 字段控件由 Schema 驱动；在确认、发布阶段分别按 `confirm`、`publish` 校验字段、类型、不适用理由和依据要求 |
| M3-05 | 依据材料管理 | 可新增、查看、替换、标注 `pending_verification/verified/invalid`；确认模块时至少一条 `verified` 依据支撑必填证据字段 |
| M3-06 | AI 建议处理契约 | 可以创建待处理建议、展示依据与置信状态、接受或拒绝；接受后创建修订，拒绝不改正式字段；AI 无确认/发布权限 |
| M3-07 | 模块状态和审核 | 支持 `not_started → in_progress → pending_review → confirmed`，退回时记录原因且可再次编辑 |
| M3-08 | 可用性和响应式 | 桌面三栏：指标树、研究详情、AI侧栏；移动端树和 AI 可收起，页面无横向滚动，键盘可到达主要操作 |
| M3-09 | 研究结论摘要边界 | 摘要位于八模块之外，来源可追溯到模块修订；AI生成摘要仅形成建议，人工确认后才成为正式摘要 |

## 自动化验证最低集

| 范围 | 最低验证 |
| --- | --- |
| 契约 | JSON Schema 语法、自校验、固定模块与字段 ID 唯一性测试 |
| API | 三级指标限制、版本隔离、权限拒绝、状态转换、乐观锁、建议采纳的集成测试 |
| 前端 | 指标树筛选、默认查看、单模块编辑、取消/保存、必填报错、未保存离开确认的组件测试 |
| 端到端 | 从导入目录到保存研究模块、审核、发布、复制版本的主路径；桌面和 390px 宽度视口 |

## M0-M3 之外的后续范围

- M4：真实模型连接、SSE 流式响应、提示词/上下文策略、模型成本与安全治理。
- M5：完整成果导出（研究卡片、Excel/Word/PPT）、质量检查任务、批量审核。
- M6：生产部署、备份恢复、性能压测、监控告警、数据分级与安全评估。
