# 一级指标新增与编辑修复

后端版本：`stage13-20260909-032202`，部署服务器：`43.139.78.226`。

一级指标数据库父节点为 `null`，原编辑逻辑将它与 `parent?.id` 返回的 `undefined` 比较，误判为移动。现将空父节点统一为 `null`，允许带子节点的一级指标修改名称、编码及排序；原移动、层级和权限检查继续生效。

新增失败源于前后端版本不一致：前端已省略编码，线上后端仍要求必填。本次补发已实现的自动编码逻辑，在体系行锁内分配内部编码，并兼容显式传入的标准编码。

验证结果：

- 新增 9 项编辑与移动边界测试。修复前两项一级指标编辑用例复现错误，修复后全部通过。
- 后端类型检查、生产构建通过。
- 构建后的服务在真实 PostgreSQL 事务中验证新增一级、二级、三级指标、自动编码续号、一级与二级带子节点编辑、显式空父节点、拒绝非法移动、空名称及权限不足；校验子节点关系与审计记录。所有临时用户、体系和指标均随事务回滚，回滚后确认无残留。
- 正式 HTTPS 健康入口返回正常，systemd 服务正常，线上源码和构建文件摘要与发布包一致。

数据库回归直接调用实际目录服务及权限实现，不代表本批重新执行完整登录或浏览器业务回归。事务回归也不替代已有自动编码并发集成测试。

本批从原后端版本复制独立发布目录，仅替换目录服务源码、构建文件及附带验证脚本，无数据库迁移。前端无需重新发布。发布脚本在切换前校验原版本及新文件摘要、执行数据库回归；切换后健康失败则恢复原版本。
