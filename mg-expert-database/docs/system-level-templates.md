# 体系分级内容模板

每个体系选择 1–6 级，默认三级。工作区顶部的「模板设置」可编辑各级模块、字段及选项。系统管理员和拥有当前体系目录管理权限的用户可维护模板。父指标与末级指标均可独立填写内容，不复制或汇总上下级内容。内容支持逐字段编辑、保存或取消，也保留整模块编辑。

## 数据规则

- 模板按体系 ID 和层级唯一；体系的各业务版本共用当前模板。
- 模块和字段使用稳定标识，改名及排序不改标识。删除必须确认，模板保存后生效。
- 新增但未保存的项直接移除；已保存项（包括有内容、依据的项）以 `deleted=true`、`active=false` 保留，从当前模板、日常填写和新语义源中隐藏，可从「已删除」恢复。不物理删除记录、依据或历史修订。
- 删除模块会隐藏其全部字段，恢复模块时保留子字段原来的停用或删除状态；至少保留一个未删除的启用模块。
- 可用其他级别的模板覆盖本级：来源级别的未删除模块和字段（含停用项）整体接管本级结构和顺序；同标识项沿用原标识，同标识但类型不同的字段改用新标识；本级不再包含的已保存模块和字段转为删除状态排在最后，可从「已删除」恢复。覆盖只改本级，不改来源级别，保存模板后生效。
- 已有内容使用过的字段禁止直接改变类型。新增字段初始为空。
- 停用选项从可选项中移除，已有选择保留。
- 内容修订快照包含当时的模板和依据；既有历史修订在迁移中补充原始模板，原内容不变。
- 保存内容校验内容修订号与模板修订号；冲突时保留输入，并可加载最新内容后对照。
- 逐字段保存仅提交目标字段，其他字段的值、不适用理由和依据不变；保存中禁止重复提交和切走，失败后保留输入供重试。
- 降低最大层级检查所有业务版本；存在更深层节点时拒绝。
- 目录导入、目录新增和同父级排序适用于所有配置层级。
- 模板变更、目录新增和内容提交通过同一体系行锁协调。

## 接口

- GET /api/systems/:systemId/templates：读取配置、各级模板及同级指标数。
- PUT /api/systems/:systemId/templates：提交 expectedRevisionNo、maxLevel、levels。
- 工作区返回 templateRevision；模块、摘要、依据提交附带 expectedTemplateRevision。
- 修订记录返回 snapshot.template，可还原停用前的字段及内容。
- 模板设置顶部的「复制级别」按其他级别的当前编辑状态覆盖本级，覆盖前确认，仍需保存模板才提交。
- 模板编辑目录支持模块及同模块内字段拖拽，顶部固定新增入口；内容项删除后仍携带其稳定标识和删除状态提交，不能从请求中遗漏已有标识。

## 本地迁移验证

以下脚本仅允许本机 5437 端口的 mg_expert 开发库，不连接生产库。先导出 public schema，在独立数据库中验证迁移，再备份并应用到本地库。

```powershell
node --env-file=.env apps/api/node_modules/tsx/dist/cli.mjs apps/api/scripts/verify-template-migration.ts
node --env-file=.env apps/api/node_modules/tsx/dist/cli.mjs apps/api/scripts/verify-template-migration.ts --apply
pnpm typecheck
pnpm test
pnpm build
```

备份和校验报告在 artifacts/template-migration-时间戳/ 下。脚本比对目录、记录、模块、依据和内容修订的数量及 SHA-256 指纹。独立测试副本保留用于核验，未自动删除。

本次开发库迁移前：9 个节点、3 条记录、24 个模块、2 条依据、3 条内容修订，迁移前后指纹一致。后续打开上级指标会按需初始化该指标的空记录。

浏览器冒烟脚本 scripts/template-ui-smoke.cjs 使用 Playwright；可通过 PLAYWRIGHT_MODULE 指定本机安装位置。它只验证模板入口、切换、预览和指标内容展示，不保存模板或改动已填写内容。

AI 助手已从本应用移除，模板不再需要为其保留兼容路径。
## 体系成员角色

系统管理员拥有全局最高权限，默认管理全部体系；任何体系成员均不能对其降权或移除访问。

创建体系的用户自动成为创建者，拥有该体系的目录、模板、内容及成员权限管理能力。创建者可以授予以下角色：

- 管理者：维护目录、模板和全部指标内容。
- 编辑者：维护全部指标内容和依据，不需逐指标分派。
- 查看者：只读。

仅创建者和系统管理员可维护成员角色。创建者不可通过普通成员授权接口降级或移除，也不能手工授予第二个创建者身份。旧体系创建者仅依照创建审计记录回填；没有可靠记录的体系由系统管理员维护，不推测创建者。历史零散授权保持原行为，保存新角色后使用角色权限。
