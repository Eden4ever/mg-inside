# 平台公共配置与复用范围

## 已提供的公共能力

- `packages/frontend/config/application-catalog.json`：桌面名称、内置应用名称及说明的公共来源。桌面目录、窗口标题与接入该配置的应用页头使用同一个应用名称；页面标题由页面配置负责。权限和部署地址不放在这个公共文件。
- `application.json`：页面、默认路径、导航模式（单层、双层、分组）、默认收起、标准/阅读布局、页头显示选项。
- 品牌：企业 Logo、深色 Logo、替代文字、首页链接、favicon、浏览器标题模板、页面说明。图片配置引用代码资源注册表中的键，禁止 JSON 指定任意远程资源或可执行代码。
- `@mg-inside/frontend/assets`：应用图片图标只有一份源文件，各应用打包时自行带上资源；不依赖桌面网站运行。图标裁切方式、内缩量来自图标 manifest。
- `ConfiguredApplicationHeader`：根据配置渲染页头；深浅主题选择对应 Logo，图片失败时降级为注册图标；桌面模式隐藏应用重复页头。
- `overlays.css`：统一 Dialog、MessageBox、Drawer 的 Windows 关闭按钮，保留组件事件、禁止关闭选项及业务关闭保护。

个人中心与应用管理作为配置接入样板。旧应用仍有部分页面结构和导航定义留在业务代码中，尚未全部迁成 JSON。

## 注册弹窗范式

弹窗声明标题、页面路径、尺寸与注册组件。业务调用同一套 `open`；浏览器呈现页面内弹窗，桌面创建同一业务应用的独立子窗口。桌面仅允许注册到本应用允许路径，不接受外站 URL。

参数与保存结果通过校验来源、窗口身份和请求 ID 的消息传输，不放 URL、不写入桌面恢复记录。子窗口保留未保存和进行中请求保护；父窗口关闭先检查子窗口。关闭、移动与最小化不依赖网络。外链应用不接入可信弹窗或认证消息桥。

现有普通弹窗不会自动跨出 iframe；需要将业务表单或详情提取成注册组件。原生 `window.confirm` 属于浏览器界面，不能通过 CSS 改样式，应逐步迁入公共确认服务。

## 后续可纳入的配置

1. 详情页面菜单选中项、动态路由关联，消除旧应用各自维护的路由/标题/导航映射。
2. 窗口默认尺寸、桌面分类与默认打开方式；服务地址继续由部署环境管理。
3. 跨应用入口使用目标 appId 与允许路径；不复制认证逻辑。
4. 文档的章节与页面分组，正文及本页锚点仍由文档内容生成。
5. 可见性引用注册的能力键，仅控制展示；后端必须继续独立鉴权。

不把业务函数、令牌、密钥、后端权限授予或敏感账户数据放入公共 JSON。版本化发布与应用脚手架仍需后续完善。
