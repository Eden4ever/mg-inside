# 资源管理应用首版规划

状态：2026-09-08 已完成初步调研，待开发；尚未创建资源管理凭据或接入云 API。

## 定位与接入

新增系统应用“资源管理”，唯一应用 ID 为 `resource-manager`，部署在 `https://desktop.meta-gravity.com/apps/resource-manager/`。共用统一身份认证和平台公共壳，默认不向普通用户开放；由用户或平台角色显式授权。平台管理员具有管理入口。应用名称不参与权限判断。

前端只处理资源展示与操作意图。后端保存资源关联、负责采集与权限检查，凭据不下发给浏览器。先建设小型资源台账和部署关系视图，避免同时引入第二套用户和权限体系。

## 首版页面

1. **概览**：资源数量、在线状态、异常服务、证书和实例到期提醒；显示最近采集时间和数据是否过期。
2. **服务器**：两台服务器的资源卡片／表格，进入详情查看 CPU、内存、磁盘、系统、网络与服务；未知数据明确显示“待采集”。
3. **应用部署**：按应用 ID 展示服务器、域名、端口、Docker／systemd、当前发布版本、最近发布时间和备份位置。Token One 三个应用分别授权，允许指向同一个服务部署。
4. **云账户与连接**：配置账户名称、地域范围、凭据引用、连接检测与最近同步结果；页面只展示凭据名称、指纹或末尾标识，不展示密钥明文。
5. **采集与审计**：采集任务、失败原因、资源变更记录、操作者与操作结果。

第一阶段提供查看、刷新采集、编辑标签／负责人／备注、查看部署关系。重启、部署、扩容、删除实例等操作纳入后续阶段，不能在第一版以任意命令框代替。

## 凭据与采集

用户已授权生成对应凭据，但授权并不等于已配置成功。

- **云 API**：腾讯云 CAM 专用只读身份，限定相关产品查询与监控接口。SecretId／SecretKey 必须由腾讯云签发，随机生成字符串不能成为云凭据。若实例支持服务角色，优先使用临时凭据。接入前验证 CVM／Lighthouse 实际类型，再确定所需 API 与资源范围。
- **SSH**：单独生成 Ed25519 密钥，由现有 1Password SSH Agent 完成首次安装公钥。新建采集账户，仅允许固定采集命令，禁止任意 shell、端口转发和代理转发；不复用或导出个人 root 私钥。记录并校验服务器主机密钥指纹。
- **保管**：平台后端持有凭据引用；密钥存储于专用受限机密目录或密钥管理服务。与应用源码、日志、备份清单分离；支持轮换和撤销。生成、安装、验证完成后才标记连接可用。
- **数据源分工**：云 SDK 获取资源属性、实例状态与云监控；SSH 固定采集器获取 Docker／systemd 运行状态及部署版本。无需为采集授予业务数据库读取权限。
- **失败行为**：保留最近成功快照，标记过期与失败原因；查询失败不代表服务器已删除。云 API 与 SSH 状态分别显示。前端关闭／拖动／导航不等待网络请求。

## 数据与权限

实体建议为 `CloudAccount`、`CredentialRef`、`Resource`、`ResourceEndpoint`、`ServiceDeployment`、`ApplicationDeployment`、`CollectionRun`、`AuditEvent`。

应用访问权限仍使用 `resource-manager`。后续细权限统一注册到平台授权域：`resources.read`、`resources.refresh`、`resources.metadata.write`、`resources.credentials.manage`、`resources.operate`。平台角色及用户均可被授权，后端逐次检查；隐藏按钮不代替鉴权。部署与服务的关联不自动授予 Token One、指标知识库等业务应用权限。

## 开源复用取舍

| 项目 | 核查结果 | 建议 |
| --- | --- | --- |
| [腾讯云 Node.js SDK](https://github.com/TencentCloud/tencentcloud-sdk-nodejs) | 官方 Cloud API 3.0 SDK，适配现有 Node.js 服务 | 首版复用采集能力，前端沿用本平台 |
| [蓝鲸 CMDB](https://github.com/TencentBlueKing/bk-cmdb) | MIT；支持模型、主机／进程、关系拓扑与审计 | 资源类型与数量扩大后评估作为资产后端；首版两台服务器引入整套平台的运维成本较高 |
| [JumpServer](https://github.com/jumpserver/jumpserver) | GPLv3 的特权访问管理平台，支持浏览器 SSH 等访问；官方快速开始建议至少 4 核 8 GB | 需要多人终端访问与会话审计时独立集成，不能将其等同于完整云资源管理系统；具体云同步功能及版本边界另行确认 |

建议：首版采用“平台公共壳＋专用资源服务＋腾讯云官方 SDK＋受限 SSH 采集器”。后续可通过适配层替换资产来源，无需让应用页面依赖某个 CMDB 的内部表结构。

## 实施顺序与验收

1. 建应用目录和台账，将两台已知服务器及部署关系登记为待连接，验证应用授权。
2. 配置腾讯云只读凭据；核实产品类型、地域和实例 ID，合并发现结果。
3. 生成并安装专用采集密钥，验证固定命令可执行、任意命令和转发不可执行。
4. 增加定时采集、健康状态和审计，验证断网、超时、凭据轮换及过期快照。
5. 通过独立浏览器／桌面窗口、窄屏、无权限用户、非授权后端请求等验收后发布。资源操作和发布编排作为后续阶段。
