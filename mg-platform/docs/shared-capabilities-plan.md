# 公共能力与应用壳演进

日期：2026-09-09。状态：公共服务请求客户端与注册/调用出口已实现，资源、文件、Office、知识库与 Token 的首批登记接口已接入并发布。其余能力按下文规划继续推进。

## 现有基础与重复点

公共 `frontend/index.ts` 已导出配置化应用壳、页头、导航、页面框架、内容面板、图标、会话、桌面 SDK 与注册弹窗。标准应用已共享结构，后续以复用和补齐行为为主。

具体重复：Files、Office、资源管理的 `src/api.ts` 都处理 fetch、CSRF、超时、401 和错误解析；Files 与资源管理各自处理请求状态及消息；Files 的名称/移动编辑器各写一套离开确认。Office 的保存还包含编辑器同步与落盘回调，它属于领域逻辑，不能把这套状态机直接作为所有表单的公共保存实现。

## 建议的四层结构

| 层 | 负责内容 | 推荐承载 |
| --- | --- | --- |
| 公共应用壳 | 导航、标题、主题、页面状态、公共交互入口 | 现有 `frontend` 组件 |
| 应用运行 SDK | 会话、请求、权限呈现、任务、导航和文件动作 | `frontend` 子入口，稳定后拆 runtime/client |
| 公共契约与后端 SDK | 服务声明、错误/分页规范、身份校验、注册发布 | 无 UI 依赖的 contracts 与 server SDK |
| 平台服务 | 身份、文件存储、服务目录、资源、通知/任务持久化 | 各独立后端，壳子调用公开契约 |

公共依赖在构建时打入应用，固定版本。独立打开应用不依赖桌面窗口存在；壳子不会运行后台采集、保存密钥或签发令牌。

## 需要补齐的公共能力

| 能力 | 共用部分 | 应用保留部分 | 优先级 |
| --- | --- | --- | --- |
| API 请求客户端 | CSRF、超时/取消、401 单次处理、403、错误格式、requestId、JSON/文件/流式适配 | 接口参数、数据解释、业务错误恢复 | P0 |
| 权限状态呈现 | 应用能力加载、加载中/无权/失败状态、菜单动作过滤、授权变化后刷新 | 后端逐次鉴权、对象归属与数据过滤 | P0 |
| 页面状态 | 加载、空结果、无权限、错误重试、离线与数据过期的统一展示 | 何时为空、何时过期、刷新内容 | P0 |
| 表单与关闭保护 | dirty/busy 汇总、离开确认、保存失败保留草稿、弹窗/路由/关闭一致行为 | 业务校验、保存事务、冲突合并；Office 落盘确认 | P0 |
| 任务呈现 | 上传/导出/采集的状态、进度、取消入口和结果跳转 | 真正的后台执行、取消语义、重试幂等性 | P1 |
| 文件动作 | 选择文件、上传反馈、下载、按类型打开、预览入口 | Files 配额/权限/存储、Office 编辑引擎 | P1 |
| 标准列表 | 筛选工具栏、分页、列偏好、选择状态、刷新行为 | 业务字段、表格列、排序规则、批量操作 | P1 |
| 通知与跨应用打开 | 消息类型、去重、目标 appId/实体 ID、已授权导航 | 通知产生规则和持久化；业务操作结果 | P1 |
| 服务声明和注册 | Schema、契约摘要、幂等提交、注册结果、发布集成 | 哪些能力可公开、接口实现、服务维护责任 | P0，与服务管理并行 |
| 服务发现和调用 | 类型化客户端、环境选择、受控入口解析、统一错误 | 业务请求处理、令牌受众、计费与数据授权 | P1/P2 |
| 观测与审计接入 | 请求关联 ID、事件格式、脱敏规则、统一错误上报接口 | 后端可信审计、业务指标含义 | P1 |

以上优先级表示实施顺序，不表示应立即把全部内容加入壳子主包。只在有实际共用行为时增加组件，不再封装一遍普通按钮和输入框。

## 第一批接口建议

以下为建议名称，并非当前已存在的 API：

```ts
// 页面只声明请求意图，平台客户端负责传输与会话行为。
const api = createApplicationClient({ appId: 'resource-manager', session });
const result = await api.get('/resources', { signal });

// dirty 的含义和保存是否真正完成，仍由业务模块提供。
const guard = createUnsavedChangesGuard({
  isDirty: () => editor.dirty,
  isBusy: () => editor.saving,
  save: () => editor.saveAndConfirm(),
});

// 文件选择返回引用，使用引用时服务端仍要核验权限。
const selection = await files.pick({ accept: ['.docx'], multiple: false });

// 发布脚本运行，凭据仅由服务端进程提供。
await registry.publish({ manifest, contracts, artifactDigest, environment });
```

公共请求层对非幂等请求默认不自动重试；重试需服务端支持幂等键。文件下载和 SSE 等流式响应不强制解析成 JSON。401 统一失效处理，403 显示无权限，网络失败不伪装成退出登录。旧响应不能覆盖新页面状态。

任务“取消”区分取消等待与真正取消执行，关闭窗口不等于停止服务器任务。只有后端提供持久化任务接口时才显示可跨刷新恢复的任务；现有资源刷新是一次请求，不能仅靠包装前端任务条就声称支持后台持久化。

## 服务管理与壳子的接点

- **共用配置**：应用清单引用服务清单位置及版本；浏览器配置只包含可公开标识，不含内网 endpoint 和发布凭据。应用声明、服务声明、部署配置各有独立 Schema，避免形成一个巨大 JSON 文件。
- **共用展示**：状态、标签、错误、版本对比容器及详情布局可复用；API 文档解析器和完整调试器留在服务管理应用，按需加载。
- **共用导航**：用 appId + 服务/资源 ID 从资源管理跳到服务详情，再跳到提供应用。桌面与独立浏览器分别适配，服务端仍检查权限。
- **共用接入**：每个提供应用用注册 SDK 随发布提交契约；每个调用应用可用类型化客户端。壳子启动不自动扫描、注册或更改生产目录。
- **共用身份**：会话与能力接口统一；目录可见权限和 API 调用权限分开。细粒度权限及机器身份未落地前，不能用前端 `can()` 当作已经实现的服务治理。

## 应保留为独立平台能力或业务能力

| 能力 | 承载位置与原因 |
| --- | --- |
| 用户、角色、权限配置和服务凭据 | 统一身份后端；壳子仅呈现结果 |
| 服务版本、契约、依赖、探测 | 服务管理后端；避免所有应用承担目录治理 |
| 文件存储与预览转换 | Files 后端，前端提供共用选择/打开入口 |
| Office 编辑与保存回调 | Office/Files；同步、签名和落盘有专门业务语义 |
| SSH、云 API、部署执行 | 资源服务及未来部署服务；不能放到浏览器 |
| 模型推理、计费、指标研究逻辑 | Token 和知识库；可注册为服务供其他应用使用 |
| 跨应用持久化通知/任务、审计存储 | 后续平台后端，壳子提供消费组件和事件契约 |

## 落地顺序和验收

1. 先提取公共请求客户端和错误模型，用资源管理、Office 两个真实消费者验证；随后迁入 Files 的上传/下载适配。保留原有协议，避免一次改动全部后端。
2. 提取页面状态和离开保护，分别使用普通表单与 Office 验证；记录 Office 的领域回调例外，验证保存失败和并发编辑。
3. 服务管理使用这些能力开发，注册资源查询和文件元数据两组服务，推动注册 SDK 与契约稳定。
4. 再补文件选择器、任务和通知接入，统一身份细权限准备好后接能力呈现与机器调用授权。
5. 更新应用模板和接入检查：壳配置可验证、无重复会话实现、无凭据进入前端、dirty/busy 实际接入、独立浏览器可用。公共包固定版本，逐应用发布。

验收覆盖浏览器/桌面、401/403/断网、请求取消和旧响应、非幂等请求不重复提交、保存失败不丢内容、无权文件引用被拒绝、角色变化刷新后生效。以两个真实应用接入证明抽象适用，再扩展到其余应用。
