# 服务管理

2026-09-09：独立数据库批次已发布。当前桌面核心及静态发布目录 `20260908T195300Z`。资源管理、文件、Office、知识库、统一身份的 `1.1.0` 及 Token `1.2.0` 契约均已启用，迁移后正式只读查询成功，六份持久化契约摘要与源码一致。

## 当前能力

- 公共壳、平台字体与页面布局、独立服务管理图标；导航保持原位置。
- 服务目录、不可变清单与契约、登记与启停、修订号并发保护、路由冲突检测、只读调用验证、调用元数据与变更记录。
- 导入 `registration.json`，或者分别粘贴清单和 OpenAPI；登记后须明确启用。
- OpenAPI 3.1.1 文档结构与 JSON Schema 2020-12 校验；参数、请求正文、响应、错误和公共数据结构浏览，下载完整契约。
- 服务 ID、提供应用、版本、操作 ID/方法/路径完整对应；清单摘要与契约摘要分别持久化，同版本任何内容变化均拒绝，JSON 键序变化可幂等重试。
- 禁止外部引用与任意上游地址；契约限 512 KiB、登记包限 600 KiB，限制嵌套与节点数量。支持 components 内部引用，暂不支持嵌套 `$id`、锚点、动态引用、webhook 和 callback。详细校验来源见桌面项目 `apps/server/src/schemas/README.md`。
- 版本差异分别显示操作变化和参数/响应/认证要求变化。结构变化保守要求人工审阅，不能把“没有操作变化”视为结构兼容证明；复杂引用超过比较上限时要求下载审阅。完整 JSON Schema 自动兼容性判定仍待继续实现。

## API 与权限

管理接口位于桌面 `/api/service-registry`。`POST /publications` 接受 `{manifest, contract}`，也兼容旧清单；`POST /activation` 接受 `serviceId`、`version`、`expectedRevision`，需适配的操作变化使用 `allowBreaking`，契约结构变化使用 `allowContractChange` 明确确认。

统一出口为 `/api/services/invoke/{serviceId}/{operationId}` 和 `/api/services/apps/{appId}/{path}`，路径变量通过 `path.{参数名}` 传入。正式后台根据运行环境和受控部署绑定选择提供方，不使用文档 `servers` 转发。未登记的应用路由仍由公共客户端走原代理。

环境发布支持选择已部署且契约摘要匹配的目标，展示实际提供方、运行资源、地址和部署时间；发布更新出口绑定，不负责安装业务程序。后台再次核对环境、修订号和部署摘要，审计保存变更前后绑定。无匹配部署的历史版本不能发布。生产目前只配置真实生产环境；跨环境隔离和两实例路由已在独立数据库 HTTP 回归中验证。操作指南见 `../mg-desktop-one/docs/service-environments.md`。

版本详情可管理生命周期：新登记为草稿，首次环境发布转为已发布；弃用保留当前调用并提供迁移说明/计划日期，阻止新增绑定；退役必须所有环境均不再使用，保留契约且不可恢复。全局状态独立修订，变更审计在各环境可见；表单接入公共弹窗和未提交保护。规则与故障边界见 `../mg-desktop-one/docs/service-lifecycle.md`。

目录按提供应用授权过滤，管理写入仅已授权的平台管理员可用；所有实际调用继续验证用户对提供应用和业务数据的权限，写入校验 CSRF。契约展示不扩大授权。机器身份仍未开放。

## 数据与发布

当前 API 仍与桌面同进程，但正式目录已使用独立 PostgreSQL 数据库与受限运行账号。13 个版本、6 个启用状态和原记录完整迁移；数据库事务支持多个目录实例并发写入。启用版本/修订/记录按环境保存，运行配置固定 production，页面显示当前环境。跨环境发布、受控部署地址绑定、生命周期与机器身份继续按平台规划推进。

数据库故障时，目录管理返回 503，已有业务调用可使用校验后的最后确认路由快照，仍执行原认证权限校验；期间调用记录可能缺失。未配置数据库的本地开发仍兼容 JSON；数据库模式不会从旧 JSON 自动覆盖新数据，也不会自行恢复停用服务。迁移、备份和回滚详见桌面项目 `docs/service-storage.md`。

独立数据库综合测试涵盖实际两个实例并发、环境隔离、受限账号、断连与快照重启、真实桌面 HTTP 及原 JSON 引擎恢复。正式数据库备份已恢复到临时数据库并核验，临时库已清理。目录的并发支持不代表其他桌面 JSON 存储已经支持多副本。

正式前端使用桌面项目 `scripts/build-service-manager-release.ps1` 构建，固定 `/apps/service-manager/` 和正式桌面域名；打包脚本拒绝根路径构建。服务端依赖已打进单文件构建产物，生产不需临时安装。

验证：桌面 36 项测试通过，包括三个服务全部 23 个操作的真实 HTTP 响应、错误响应、下载字节、两账户隔离、Office 签名回调落盘、契约篡改、初始化和版本保护；真实本地登录链路通过。正式目录显示六契约启用，六服务只读调用成功。Office 固定提供方前缀为 `/api/office`，其余契约为 `/api`，文档不能覆盖实际代理绑定。

知识库契约另经独立 PostgreSQL、真实登录和 HTTP 验证，涵盖三查询、体系共享授权、管理员全局范围、撤销、空版本和语义构建状态。该测试与桌面测试合计覆盖四服务 26 个操作；不是所有业务接口的完整回归。

Token 的两个目录另经真实 HTTP 控制器、身份 Guard 与分组服务验证，身份与仓储为受控替身；生产公开响应直接通过 Schema 校验。统一身份本人资料另经独立 PostgreSQL Schema、真实密码登录、Nest 控制器与会话 Guard 验证，覆盖双账户、实时角色及应用授权、会话失效和敏感字段边界。六服务已登记操作契约齐备，不代表整个治理规划或全部业务接口完成。
