# ADR-0001：模型、模型所有者与供应商分层路由

## 状态

已采纳，双写迁移阶段。

## 背景

Token One 当前的 `ModelConfig.bindings` 已经允许一个对外模型绑定多个渠道，但绑定只记录 `channelId`、上游模型名和优先级，无法表达模型所有者、官方/第三方供应商、供应商账户和供应商侧模型目录。继续把 CCTQ 直接写成模型或渠道字段，会让余额同步、计费和自动切换互相耦合。

## 决策

采用三层业务关系：

```text
模型（对外能力）
  -> 模型所有者（OpenAI / Anthropic / DeepSeek）
  -> 模型路由（可执行映射）
       -> 供应商（官方 / 第三方）
       -> 供应商账户（余额 / 套餐 / 凭据）
       -> 渠道（端点 / 协议 / 密钥 / 健康）
```

- 一个模型通常有一个主模型所有者。
- 一个模型可以有多个模型路由，因此可以同时连接官方供应商和第三方供应商。
- 一个供应商可以提供多个模型，一个供应商账户可以承载多个渠道。
- CCTQ 作为第三方供应商可以跨模型所有者供给模型，因此供应商实体不持有单一模型所有者外键；二者的关系由模型路由推导。
- 路由选择由渠道池负责；供应商账户适配器只负责账户状态和目录同步。
- 账户余额、供应商成本和 Token One 客户余额保持独立，不直接互相替代。

## 路由行为

- 同一对外模型的多个路由按优先级、权重和健康状态选择。
- 当前渠道连续失败时，渠道池可以在同一模型的其他供应商路由之间故障转移。
- 余额不足或账户快照过期默认只产生告警；自动禁用必须是显式策略。
- 路由必须满足协议和能力约束，不能因为模型名称相同就假定 Responses、Anthropic、图片或工具调用能力相同。

## 迁移策略

`model_routes` 是模型与渠道多对多关系的权威存储，独立记录上游模型名、优先级、权重和启用状态。管理端通过一个持久化模块在同一事务中写入 `model_routes` 与 `ModelConfig.bindings`；后者只作为旧镜像回滚副本，不再参与新版本路由读取。

数据库迁移从旧 JSON 回填显式路由，并继承原渠道权重。渠道池、渠道删除保护和渠道探测统一读取显式路由。完成至少一个发布周期和回滚演练后，再单独决定何时停止兼容双写和删除旧字段。

## 结果

这个分层支持同种模型的手动快速切换、按优先级自动切换、供应商级余额保护和未来多供应商适配，同时避免把 CCTQ 管理员接口误当成通用客户接口。
